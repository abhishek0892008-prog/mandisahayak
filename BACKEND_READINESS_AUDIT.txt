PURPOSE
This document describes the frontend gaps and the required backend integration work
needed to turn the current Mandi Sahayak UI prototype into a working application.

CURRENT STATUS
- Frontend: React 19 + Vite + React Router + Tailwind + i18next.
- Production build: passes (npm run build).
- Lint: fails with 6 errors caused by synchronous setState calls inside effects.
- Network/API layer: none. No fetch, Axios, React Query, or backend client exists.
- Authentication: not implemented.
- Data persistence: browser localStorage and hard-coded sample values only.

CRITICAL DEFECTS TO FIX FIRST
1. Missing booking confirmation route
   - src/pages/farmer/BookSlot.jsx navigates to /booking-confirmation after creating
     a booking.
   - src/App.jsx does not define this route.
   - Add a BookingConfirmation page and route, or navigate to an existing valid page.

2. OTP is only visual; no authentication exists
   - Registration writes farmer data to localStorage and navigates to OTP.
   - Login does not retain or submit the mobile number.
   - OTP verification accepts any six digits and navigates to dashboard.
   - Resend OTP button has no action.
   - Implement send OTP, verify OTP, resend OTP, error handling, expiry, rate limits,
     resend cooldown, and secure session creation.

3. Do not use localStorage as application data storage
   - farmerData contains name, phone, district, village, Aadhaar last four digits and IFSC.
   - bookingData and bookingHistory can be changed by the user from browser tools.
   - Remove localStorage as the source of truth for profile, booking, payments, and queue.
   - Use it only for non-sensitive preferences if needed, e.g. language selection.

4. Hard-coded business data must come from backend
   - Centres, crops, slot capacities, booking ID generation, queue token, queue position,
     procurement state, payment state, and notifications are not real data.
   - Backend must own all of these values and enforce all business rules.

5. No route access protection
   - Any user can open /dashboard, /profile, /queue, /payment etc. directly.
   - Add frontend ProtectedRoute handling and backend authorization for every private API.

SECURITY AND DATA RULES
- Enforce HTTPS.
- Use server-side authorization; never rely on the frontend for access control.
- Rate-limit OTP send/verify endpoints by phone, IP, and device as appropriate.
- Store OTP values hashed, with expiration and maximum verification attempts.
- Use HttpOnly, Secure, SameSite cookies where practical; protect state-changing endpoints
  from CSRF if cookie authentication is used.
- Validate and normalize every input on the backend.
- Enforce slot capacity with a database transaction/locking strategy.
- Generate booking IDs and tokens on the server.
- Keep PII minimal, encrypt sensitive fields at rest, and restrict staff access.
- Keep audit logs for booking, cancellation, procurement, and payment changes.
- Define retention and consent requirements before collecting identity/bank information.
